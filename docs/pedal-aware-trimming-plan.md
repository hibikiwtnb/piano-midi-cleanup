# 踏板感知的音符截斷改進建議

## 目標與範圍

在現有條件下，為重疊截斷增加保守的踏板檢查，降低提前 note-off 造成聽感改變的風險。保留既有快速音群、換和弦、外聲部及超跨度規則，由它們提出候選截斷點。

保守踏板檢查與相容控制器映射已接入程式，已完成 8 首既有 MIDI 的後處理對比及小型事件案例驗證，尚未渲染試聽。第一版以保持播放延音為優先，不保證截完後所有按鍵數／跨度都符合限制，也不宣稱跨音源完全無聲學差異。不新增 GUI 參數或模式。

相關研究背景：`docs/research-landscape.md` 第 12–14 節。

踏板本身的快速切換與平滑研究見 `docs/pedal-smoothing-research.md`。若加入踏板平滑，必須先定案最終踏板時間線，再執行本文件的音尾檢查；不可先截斷再改踏板。

## 目前實作

- `src/trim_overlaps.py`：`release()` 經共用 `PedalGuard` 檢查後才提前 `new_end`，所有截斷規則使用同一檢查。接受條件為推算止音點提前不超過 `SUSTAIN_TOLERANCE_SECONDS`（0.1 秒），見第 3 節。
- `write_note_ends()` 只移動接受的音尾，保留其他事件的絕對時間與未改動事件間的相對順序；沒有接受的截斷時不重寫 MIDI。
- `src/hand_split_channels.py`：`map_pedal_channels()` 在改寫音符聲道前映射相容踏板／持音與 channel mode 控制；不相容時於儲存分手前報錯。
- `src/postprocess.py`：先分手，再截斷；截斷也可經獨立入口呼叫，不能假定每份輸入都已正確分配踏板。
- 超跨度分支依實際 `new_end` 重建 `held_notes`，拒絕截斷的長音繼續參與後續判斷。

## 1. 先確保踏板與音符 channel 對應

CC64 是逐 channel 的控制訊息，不是逐 track 的全局開關。跨軌讀取控制事件時應使用絕對 tick，保留其 channel 與原始順序。

最小支援範圍先涵蓋單一來源鋼琴 channel 分成多手：

1. 在改寫音符 channel 前記錄來源 channel 與實際使用的目的 channel。
2. 將來源 CC64 序列正確映射到所有使用它的目的 channel，保持 tick、value、相對事件順序；來源 channel 若也是目的 channel，不能留下衝突的重複序列。
3. 目的聲道既有不同 CC64、多來源 channel 互相混入同一目的聲道等情況，不能直接覆蓋、OR 合併或把任意一軌視為全局踏板。第一版標示未支援／有歧義，對受影響音符保留原音尾。
4. 獨立截斷入口僅依檔案實際對應的控制資訊判斷；不要從其他 channel 猜測踏板。

保留既有其他控制器；遇到 CC66 持音踏板、CC120／121／123 等會影響持音或重設狀態的事件，第一版保守拒絕相關區段的截斷。不要擴成完整 MIDI 模擬器。

實作前確認多來源衝突是否能在現有資料流中明確辨認；若無法保留必要資訊，先讓該類輸入不截斷，不能以錯誤的踏板時間線繼續處理。

## 2. 建立踏板區間

按 channel 建立 CC64 時間線。基本開關採 MIDI 定義：0–63 關、64–127 開。同一踩下區間內的重複 on 事件不應切成數個區間。

第一版可只對明確的 0／127 全關／全開序列放行；其他值視為可能的半踏板，保留原音尾並計數。閾值只能描述基本開關狀態，不能證明不同半踏板值的音色與衰減完全相同。

缺少明確踩下與鬆開界線、不完整區間或控制事件順序有歧義時，不以「推測踏板還踩著」放行。

## 3. 每次截斷的接受條件

設原始音尾為 `original_end`，這次候選為 `candidate_end`。按二值 CC64 推算止音點：note-off 落在踩踏板期間時，聲音延到下一次鬆踏板；未鬆開的踏板延到檔案結尾。

僅當下列條件全部成立，才縮短音尾：

- `start_tick < candidate_end`，不可產生零長／負長音。
- 候選止音點比原始止音點提前不超過 `SUSTAIN_TOLERANCE_SECONDS`（0.1 秒）。
- 踏板事件與音尾同 tick 時先後不明：原始止音點取較晚的解讀，候選止音點取較早的解讀。
- 該 channel 沒有半踏板值（非 0／127）、CC66／69、channel mode 控制或不完整音符配對；同音高沒有在 `[candidate_end, original_end]` 內重疊的其他音。

候選始終和不可變的 `original_end` 比較，避免連續多次縮短累積超過容差。

沒有踩踏板時，只要截斷量本身不超過容差即可接受；超過則保留。

### 具體例子

踏板第 1 秒踩下、第 4 秒鬆開；音符第 1.5 秒起音：

| 原 note-off | 候選 note-off | 決策 | 理由 |
|---|---|---|---|
| 3 秒 | 2 秒 | 接受 | 兩者止音點都是第 4 秒鬆踏板 |
| 4.05 秒 | 2 秒 | 接受 | 止音點由 4.05 秒提前到 4 秒，在容差內 |
| 5 秒 | 2 秒 | 保留 | 止音點由 5 秒提前到 4 秒 |
| 3 秒 | 0.95 秒 | 保留 | 候選早於起音 |
| 3 秒 | 1 秒 | 保留 | 與踩踏板同 tick，取較早解讀時止音點為 1 秒 |
| 4 秒 | 2 秒 | 接受 | 原 note-off 與鬆踏板同 tick，兩種解讀止音點都是 4 秒 |

無踏板時，原 note-off 2.08 秒、候選 2 秒可接受；原 2.3 秒、候選 2 秒保留。

「止音點提前不超過容差」不代表音源輸出逐樣本相同。釋放聲、共鳴與重彈行為仍需試聽確認。

## 4. MIDI 事件如何改

- `note_on`：時間、音高、力度不變，不補發起音。
- `note_off`（含 velocity 0 的 note-on）：通過條件才把絕對 tick 改到候選點；其餘屬性保持原樣。
- CC64：截斷階段不改其時間或值；分手階段只做必要且可明確判定的聲道映射。
- 更新絕對時間後重算 delta tick；不得改變其他事件的絕對時間。
- 保留未改動事件間的原始順序，避免全局把所有原有 note-off 重排到控制器之前。跨軌同 tick 的歧義以跳過處理為優先。

### 具體例子

踏板第 1 秒踩下、第 4 秒鬆開；音符第 1.5 秒起音：

| 原 note-off | 候選 note-off | 決策 | 理由 |
|---|---|---|---|
| 3 秒 | 2 秒 | 符合其餘條件才接受 | 都在同一次踏板內，基本延音終點仍由第 4 秒鬆踏板決定 |
| 5 秒 | 2 秒 | 保留 | 新版第 4 秒可能止音，原版仍持鍵到第 5 秒 |
| 3 秒 | 0.8 秒 | 保留 | 候選早於起音，也早於踩踏板 |
| 3 秒 | 1 秒 | 保留 | 與踩踏板同一時刻，屬第一版跳過的邊界 |
| 4 秒 | 2 秒 | 保留 | 原 note-off 與鬆踏板同 tick，第一版不處理邊界 |

「基本延音終點相同」不代表音源輸出逐樣本相同。釋放聲、共鳴與重彈行為仍需試聽確認。

## 5. 接入既有規則與報告

優先在共用的候選釋放位置加入檢查，避免四種規則各自複製踏板邏輯。`release()` 可以回傳是否實際改動，原有規則計數只統計接受的改動。

所有規則都必須依實際 `new_end` 維護仍持有的音符。拒絕截斷後，不得直接丟掉仍持續的音，也不得讓下一條規則繞過踏板檢查。

報告至少區分實際截斷、因踏板不足／跨界保留、因聲道或事件歧義保留。反覆提議同一顆音時，區分提議次數與唯一音符數，勿讓讀者誤認為刪改了更多顆音。沿用現有報告區塊更新和三語顯示機制；不新增 GUI 控制項。

## 6. 驗收建議

實作 agent 先讀適用的 AGENTS 指示。以下是驗證設計，不表示授權執行耗時的整曲轉譜／批次渲染。

- 以小型 MIDI 事件案例檢查同踏板區間、跨鬆踏板、沒有踏板、半踏板、缺失 pedal-up、重複 on、同 tick 邊界、同音重彈及多軌控制器。
- 檢查單來源分成 2／3／4 手後的踏板映射，以及多來源衝突不被擅自合併。
- 檢查拒絕截斷後，後續規則仍追蹤原長音；未通過的音尾與所有 note-on 不變。
- 檢查事件絕對 tick、有效 delta tick 及未修改事件的相對順序。
- 再以相同音源、相同控制器與固定輸出設定比較少量短片段。音訊差值可輔助定位，不等於可察覺性結論；保留盲聽或人工試聽。
- 不以「最多同時按鍵數下降」單獨證明成功；可能含踏板延音的音長不是實際持鍵真值。

## 7. 預估改動範圍

主要落在 `src/trim_overlaps.py`、`src/hand_split_channels.py`，以及必要的 `src/gui_i18n.py` 報告翻譯。優先沿用現有模組，不引入模型、服務或新的音訊架構。

初步判斷是小到中等改動，實作約一兩百行量級；若處理多來源聲道衝突需要額外資料流，規模會增加，第一版應以保守跳過控制範圍。此數量不含新增驗證案例，也不是完成時間承諾。

## 8. 門檻嚴格度審查

依據：`testdata/pedal-trim-comparison-20261023-145634` 的 8 首對比資料。以新版分手後、截斷前的共同輸入（`latest_before_trim.mid`）重建各聲道 CC64 區間，再將舊版截斷的 10,397 顆音逐一分類。「聽感差距」指依二值 CC64 語義推算的止音點提前量，未渲染音訊或試聽。

### 結論

方向合理，但零容差門檻過嚴。截斷數減少 63% 不是程式錯誤，而是「推算止音點必須完全不變」的直接結果；對比報告中「新版改變推算止音點 0」由條件本身保證，不構成聽感驗證。被拒絕的截斷中，有相當比例的差距只有數十毫秒。

### 分類結果

| 類別 | 數量 | 推算聽感差距 |
|---|---:|---|
| C：截斷點與原音尾在同一次踏板內（新版接受） | 3,138 | 0 |
| B：截斷點有踏板，但原音尾晚於鬆踏板 | 3,434 | 中位 71 ms；54% ≤ 100 ms |
| A：截斷點沒有踏板 | 3,825 | 中位 222 ms；34% ≤ 100 ms，53% ≤ 250 ms |

- B 類原音尾超過鬆踏板的時間：中位 66 ms，46% ≤ 50 ms，56% ≤ 100 ms。轉譜的踏板與放鍵各自估計，這類小偏差多半仍是踏板造成的重疊，即本步驟原本要處理的對象，卻被嚴格的 `original_end < pedal_up` 全數擋下。原音尾與控制事件同 tick 一律歸為不明，屬同類問題。
- A 類無踏板截短確實縮短發聲，拒絕合理；其中差距 ≤ 100 ms 的部分聽感影響小，是否放行屬可接受聽感變化的取捨。
- 結果高度依賴轉譜踏板的完整度。《A song for You》踩踏板時間僅約 14%，截斷由 654 降至 60；若為轉譜漏踏板，截斷即實質失效。
- 本步驟目的為「使五線譜與樂譜更整齊」，新版最多同時按鍵數升至右手 11–19，此目的被大幅削弱。

### 處理

依上述審查改為容差判斷（第 3 節），容差定為 0.1 秒，無踏板的截斷同樣適用。以同一批 8 首共同輸入（`latest_before_trim.mid`）重跑截斷：截短 7,914 顆，因提前超過容差保留 2,653 顆，事件不明保留 0 顆；以獨立實作重算，最大止音點提前 99.9 ms。最多同時按鍵數右手 9–14、左手 4–10。尚未渲染試聽。

## 9. 更積極截斷的研究（La la 勇気のうた，未定案）

依據：`docs/lala-bytedance-transkun-comparison.md` 的三模型對照資料。字節 135 BPM 對齊副本經兩手分配與現行截斷後，與 Transkun V2（預設權重不把踏板延音併入音長，音尾較接近放鍵）逐音配對：同音高、起音差 ≤ 50 ms。以 Transkun 音尾作放鍵的近似參考；它也是模型輸出，不是正確答案。僅此一曲，尚未對照原音試聽。

### 第 35 小節右手截斷不足的原因

逐顆追蹤截斷候選：右手第 2.5–3.8 拍起音的長音，現有規則都有提出截斷，全部因提前超過容差被踏板保護拒絕；它們都在本小節內結束，沒有跨小節線。

| | 延音踏板（拍位） |
|---|---|
| 字節 | 1.40 踩、2.96 放、4.22 踩、4.76 放 |
| Transkun | 1.01 踩、3.95 放、4.09 踩、4.77 放 |

字節踏板在 2.96–4.22 拍之間放開約 0.56 秒，但字節音符模型認為這些音一直響過這段空檔，音尾集中在 4.5–4.8 拍、貼近下一次鬆踏板。按字節踏板，截短會讓止音提前 1 秒以上；按 Transkun 踏板則在容差內。可能是字節踏板模型提早放開，也可能是實際演奏的斷開，尚無法判定。

### 字節與 Transkun 的踏板特徵（全曲）

| 項目 | 字節 | Transkun |
|---|---:|---:|
| 踩下次數 | 312 | 177 |
| 每次踩下時間中位數 | 0.35 秒 | 0.67 秒 |
| 踩下短於 0.3 秒 | 115 | 21 |
| 放開空檔中位數 | 0.13 秒 | 0.12 秒 |
| 放開空檔 0.2–0.8 秒 | 78 | 24 |

一般換踏板的空檔兩者相近；字節多出許多短暫踩下與偏長的放開空檔。流行曲抒情伴奏常見的切分踏板是長時間踩著、換和弦時短暫放開，Transkun 較接近此型態。節奏型段落也可能刻意多次踩放，零碎不等於錯誤。

以「踏板放開空檔中有至少 3 個不同起音的音響過整段」作為踏板可能放錯的訊號（空檔至少 1/4 拍）：

| 響過空檔的不同起音數 | 空檔數 | Transkun 該段踏板踩著 ≥ 80% |
|---|---:|---:|
| 0 | 57 | 6（11%） |
| 1–2 | 65 | 8（12%） |
| 3 以上 | 69 | 34（49%） |

訊號有區分力，但與 Transkun 只有約一半吻合，不足以直接改寫踏板判斷。曾在 8 首測試資料中以「遠離踏板的音是否集體止音」檢查整首漏判，結果不支持（見 `docs/research-landscape.md` 第 14 節）；本節是局部提早放開，與整首漏判不同。

### 跨節拍線與小節線的持續音

對現行截斷後仍跨線的音，取其跨過的第一條線，在線上試截並以現行保護判定；起音在線前一個十六分音符內者視為正拍音，不計入。

跨節拍線共 869 次，其中 558 次越線不足一拍：

| 線上試截的保護判定 | 同手在線上 ±1/8 拍內有新起音 | 次數 | Transkun 也在線前結束 |
|---|---|---:|---:|
| 允許 | 有 | 170 | 146／160（91%） |
| 允許 | 無 | 118 | 81／106（76%） |
| 拒絕 | 有 | 339 | 290／325（89%） |
| 拒絕 | 無 | 242 | 117／212（55%） |

被拒絕的 581 次若改用 Transkun 踏板判斷，371 次在容差內。允許的部分目前未被截斷，是因為新起音不構成換和弦、外聲部、超跨度或快速音群，現有規則沒有提出候選，不是保護擋下。

跨小節線共 189 次，按線後殘留長度：

| 線後殘留 | Transkun 也在線前結束 | 其中保護允許 |
|---|---:|---:|
| ≤ 1/4 拍 | 127／128 | 122 |
| 1/4–1/2 拍 | 11／11 | 0 |
| 1/2–1 拍 | 13／14 | 0 |
| 1–2 拍 | 4／4 | 0 |
| > 2 拍 | 11／15 | 0 |

殘留長度以拍數計可隨速度變化並對應譜面；殘留與線前長度的比例沒有提供額外區分。Transkun 認為音確實延續的反例都在殘留超過 2 拍處。現行保護只允許殘留 ≤ 1/4 拍者（本曲 1/4 拍約 0.11 秒，接近容差）；殘留較長者都被拒絕，因為演奏者多在小節線附近換踏板。

### 目前的判讀

- 候選方向一：持續音跨節拍線且同手在線上有新起音時，以該線作截斷候選，仍經踏板保護。允許部分與 Transkun 吻合 91%，聽感依二值 CC64 推算不變。
- 候選方向二：跨小節線截斷加「線後殘留 ≤ 1/2 拍」條件。在現行保護下本曲不會增加截斷數，作用是避免日後誤截長音。
- 更積極截斷的主要限制是字節踏板時間線本身。是否以及如何修正或繞過，尚未判定。

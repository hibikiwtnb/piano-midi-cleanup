# 「分離與轉錄」分頁設計（草案）

2026-11-10 起草，尚未實作。

## 目的

現在從一首歌做到 MIDI 要經過好幾個工具：先用外部工具把鋼琴分離出來，再雙擊 `transcribe.command` 或 `transcribe.cmd` 轉譜，最後回到面板整理。新分頁要把前兩步搬進面板，放在最前面：

```
分離與轉錄 │ 處理 │ 鋼琴捲簾 │ 詳細報告 │ 關於
```

使用者拖進一首歌，選好引擎，按一個按鈕就得到 MIDI，接著直接進「處理」分頁。引擎套件隨安裝一起裝好，模型權重在第一次使用時自動下載，使用者不必另外裝分離工具或轉譜工具。

## 拖放與路徑辨識

拖進來的東西依類型處理：

| 拖入 | 行為 |
|:---|:---|
| 音訊（flac、wav、mp3、m4a、aif、aiff、ape） | 填入路徑，讀出長度、取樣率、聲道顯示在拖放區；檢查輸出檔是否已存在 |
| MIDI | 不在這個分頁處理：切到「處理」分頁並選好這個檔案 |
| 多個音訊 | 排成佇列，依序處理，每首一行狀態 |
| 資料夾或其他檔案 | 在拖放區顯示「不支援的檔案」，不改動目前的選擇 |

**自動辨識已完成的步驟**：檔名已帶 `_piano` 的音訊，預設選「不分離」。同資料夾已有分離檔就跳過分離，已有 MIDI 就跳過轉錄，並在輸出清單標出「已存在，跳過」。可以勾選「重新產生」強制重跑。這延續現有 `transcribe.py` 的行為：「已有 MIDI 不重轉，只補缺少的檔案」。

**完成後交接**：轉錄完成時，「處理」分頁自動填入：
- MIDI：轉出的檔案。
- 速度來源：「從音訊偵測速度」，音訊為原曲。

然後切過去，使用者只要按「開始處理」。也可以勾選「完成後直接處理」，連處理一起跑完，直接跳到卷簾。

## 引擎

清單之後可以再加，第一版建議先做下面幾個。

### 分離

| 選項 | 說明 | 狀態 |
|:---|:---|:---|
| BS-RoFormer SW（六軌，取鋼琴）| 本專案比較過：比舊版 lalal.ai 乾淨，略遜 v6，低音區要另外確認（`separation-lalal-bsroformer-comparison.md`） | 現在只有本機 Swift / Core ML 版，只能在 macOS 用；要找能在 Windows 跑的 PyTorch 或 ONNX 版本 |
| Demucs htdemucs_6s（六軌，取鋼琴）| 廣泛使用、pip 可裝、跨平台 | 未在本專案比較過鋼琴品質 |
| 不分離 | 輸入已是鋼琴獨奏，或已經用 lalal.ai 等工具分離好 | — |

預設建議用 BS-RoFormer。分離結果另存為 `<歌名>_piano.wav`，保留下來，方便之後換轉錄引擎重轉。

### 轉錄

| 選項 | 說明 |
|:---|:---|
| Piano Transcription（字節，預設）| 現在用的模型，約 165 MB，CPU 可跑。整理規則的門檻都是依它的輸出定的 |
| Transkun V2 | pip 可裝，CPU 約 100 秒一首。音尾是放鍵時間，不含踏板延音。選它時，「處理」分頁要自動關掉依賴字節音長的規則（高音泛音清除等） |

MuScriptor Large 需要 GPU，一首要幾分鐘，輸出沒有力度和踏板，不適合當一般選項，第一版不放。

每個選項旁的 ⓘ 用一兩句話說明差異，例如「最常用」「比較快，音尾較短」。比較細節寫在文件，不放進介面。

## 執行方式

- 在背景程序執行，介面不凍結；可以取消。取消時刪掉未完成的檔案，已完成的檔案保留。
- 模型權重第一次使用時下載，顯示大小和進度。延續 `ensure_checkpoint()` 的作法：先下載到暫存檔，下載完整才換上正式檔名。
- 運算裝置：自動依序選 CUDA、Apple GPU（MPS）、CPU，也可以手動指定。CPU 跑分離會很慢，要在預估時間裡顯示出來。
- 設定（引擎、裝置、輸出位置）存進 `~/.piano-midi-cleanup-panel.json`，下次打開沿用。
- 舊的 `transcribe.command` 和 `transcribe.cmd` 保留一段時間，改成打開面板並切到這個分頁。

## 實作前要確認

1. **拖放能不能做**：Tkinter 本身不支援從 Finder 或檔案總管拖檔案進來。本機的 Tk 9.0.3 沒有 tkdnd。候選做法：
   - 加 `tkinterdnd2` 套件：要確認它附的 tkdnd 能在 Tk 9 下載入，Windows 和 macOS 都要試。
   - 備案：保留「選擇…」按鈕和可貼上路徑的輸入框；macOS 另外支援把檔案拖到 Dock 上的 App 圖示。
   - 這決定拖放區是主要入口還是附加功能，要最先驗證。
2. **BS-RoFormer 的跨平台版本**：沒有 Windows 能跑的版本，就先以 Demucs 當跨平台預設，BS-RoFormer 只在 macOS 提供。
3. **安裝體積**：多兩個引擎和權重，下載量會增加數百 MB。README 的安裝步驟要更新；權重不放進 repo。
4. **檔名規則**：`<歌名>_piano.wav` 和 `<歌名>_piano.mid` 會改變現有的輸出檔名，原本是 `<音訊名>.mid`。卷簾版本側欄和「沿用已修正的速度」都依檔名找檔案，要一起檢查。
5. **速度偵測用哪個音訊**：原曲有鼓、拍子比較清楚，但前奏可能有變化；分離後的鋼琴和 MIDI 時間完全一致。要用幾首歌比較兩者偵測出的 BPM，才能決定預設。

## 不做

- 不做商業分離服務（lalal.ai 等）的串接；用了那些服務的人選「不分離」。
- 不做人聲、鼓等其他軌的轉錄。

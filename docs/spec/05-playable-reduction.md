# 5. 可彈性清理（可選）

## 目的

做一個人彈的譜時，刪掉兩隻手同時按不到的音。預設關閉。

程式：`src/playable_reduction.py`。`evaluate_reduction(...)` 回傳 `kept`、`removed`、`loss`，同時供獨立清理與三手分手 beam 使用。兩隻手時在規則清理之後、分手之前執行，處理全部的音。

三隻手的曲子由兩個人彈：第一個人的左手彈低音（left）、右手彈中聲部（right），第二個人的右手彈最上面（second_right）。一個人的兩隻手在音高上一定相鄰。三手模式不再先分手再獨立清理，而是在同一個 Primo 束搜尋中比較「全部音符二手」、「刪少量音二手」與「Primo」；選中的刪音直接從輸出 MIDI 移除。四隻手不支援。

兩手時順序仍是先可彈性清理、後分手；執行器會把 `playable.max_notes` 與 `playable.max_span` 一併交給分手，讓原本已可彈到的組在分手時也維持在相同限制內。清理後仍未解決的組會保留全部音符；分手時若該組沒有符合限制的切法，全部原本不受限制的候選切法仍然可用，由一般束搜尋成本決定分配，不刪音也不中斷。未解決的組由可彈性清理列在報告中。

## 三手整合

三手的每個起音組同時考慮：

- **全部音符二手**：不刪音，使用既有兩手 assignment cost。
- **精簡二手**：用本文件的規則找出最少且最低成本的刪法，再加刪音 loss 與兩手 assignment cost。
- **Primo**：全部音符使用三手 assignment cost，外加 Primo activation／upkeep 與 `SECOND_HAND_NOTE_COST`。

因此「刪一顆音就不用叫 Primo」與「叫 Primo 以保留音符」會在同一個 beam 中競爭；不會先決定 Primo 再事後刪音。`--hands 3` 自動啟用，`--playable` 可省略，寫了也不會重複清理。

## 方法

對每個起音組（50 ms 內同時起音的音）：

1. **判斷能不能彈**：把音由低到高切成兩段，低段給左手、高段給右手。只要有一種切法讓兩手都不超過最多音數與最大跨度，就算彈得到。
2. **彈不到時刪音**：從刪 1 顆開始，最多刪 `MAX_REMOVALS_PER_GROUP` 顆；在能讓這組彈得到的刪法中，選成本最低的。
3. **刪了還是彈不到**：保留原樣，記為未解決。

刪除成本（越低越先刪）：

| 情況 | 成本 |
|---|---|
| 同組另一個八度有同音名的音（重複音） | 1 |
| 沒有重複的音 | 3 |
| 是組內最高音（旋律）或最低音（低音） | 再加 5 |
| 力度 | 再加 力度 ÷ 1000，同條件下先刪較輕的 |

## 參數

| 參數 | 預設 | `--set` | 說明 |
|---|---|---|---|
| `DEFAULT_MAX_NOTES_PER_HAND` | 4 | `playable.max_notes` | 每手最多音數 |
| `DEFAULT_MAX_SPAN` | 12 | `playable.max_span` | 每手最大跨度（半音） |
| `MAX_REMOVALS_PER_GROUP` | 3 | `playable.max_removals` | 每組最多刪幾顆 |

## 報告

`MIDI playable reduction stats`：起音組數、刪減組數、未解決組數、刪除音數（其中最高或最低音的數量），以及每處刪除的位置與音名。三手整合時，同一份資訊也記在 `MIDI provisional hand split stats`，並另列 Primo 區段、第二右手音數、Primo 成本與純二手替代成本。

## 已知限制

- 只看同時起音的音數與跨度，不看前後動作：手移動太遠來不及、仍按著前一和弦時又彈新音、超過 50 ms 的琶音都不處理。
- 不看時值與速度，處理不到短和弦快速重複。
- 不知道哪些音在音樂上重要，只以最高、最低音和八度重複近似。改進建議見 [刪音策略的改進建議](../playable-removal-strategy.md)。
- 四手的曲子不適用；三手只處理第一個人的兩隻手，且與 Primo 一起做聯合決策。

詳見 `docs/open-issues.md`。

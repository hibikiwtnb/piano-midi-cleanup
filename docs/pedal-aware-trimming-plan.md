# 踏板感知的音符截斷改進建議

## 目標與範圍

在現有條件下，為重疊截斷增加保守的踏板檢查，降低提前 note-off 造成聽感改變的風險。保留既有快速音群、換和弦、外聲部及超跨度規則，由它們提出候選截斷點。

保守踏板檢查與相容控制器映射已接入程式，已完成 8 首既有 MIDI 的後處理對比及小型事件案例驗證，尚未渲染試聽。第一版以保持播放延音為優先，不保證截完後所有按鍵數／跨度都符合限制，也不宣稱跨音源完全無聲學差異。不新增 GUI 參數或模式。

相關研究背景：`docs/research-landscape.md` 第 12–14 節。

踏板本身的快速切換與平滑研究見 `docs/pedal-smoothing-research.md`。若加入踏板平滑，必須先定案最終踏板時間線，再執行本文件的音尾檢查；不可先截斷再改踏板。

## 目前實作

- `src/trim_overlaps.py`：`release()` 經共用 `PedalGuard` 檢查後才提前 `new_end`，所有截斷規則使用同一檢查。
- `write_note_ends()` 只移動接受的音尾，保留其他事件的絕對時間與未改動事件間的相對順序；沒有接受的截斷時不重寫 MIDI。
- `src/hand_split_channels.py`：`map_pedal_channels()` 在改寫音符聲道前映射相容踏板／持音與 channel mode 控制；不相容時於儲存分手前報錯。
- `src/postprocess.py`：先分手，再截斷；截斷也可經獨立入口呼叫，不能假定每份輸入都已正確分配踏板。
- 超跨度分支依實際 `new_end` 重建 `held_notes`，拒絕截斷的長音繼續參與後續判斷。

## 1. 先確保踏板與音符 channel 對應

CC64 是逐 channel 的控制訊息，不是逐 track 的全局開關。跨軌讀取控制事件時應使用絕對 tick，保留其 channel 與原始順序。

最小支援範圍先涵蓋單一來源鋼琴 channel 分成多手：

1. 在改寫音符 channel 前記錄來源 channel 與實際使用的目的 channel。
2. 將來源 CC64 序列正確映射到所有使用它的目的 channel，保持 tick、value、相對事件順序；來源 channel 若也是目的 channel，不能留下衝突的重複序列。
3. 目的聲道既有不同 CC64、多來源 channel 互相混入同一目的聲道等情況，不能直接覆蓋、OR 合併或把任意一軌視為全局踏板。第一版標示未支援／有歧義，對受影響音符保留原音尾。
4. 獨立截斷入口僅依檔案實際對應的控制資訊判斷；不要從其他 channel 猜測踏板。

保留既有其他控制器；遇到 CC66 持音踏板、CC120／121／123 等會影響持音或重設狀態的事件，第一版保守拒絕相關區段的截斷。不要擴成完整 MIDI 模擬器。

實作前確認多來源衝突是否能在現有資料流中明確辨認；若無法保留必要資訊，先讓該類輸入不截斷，不能以錯誤的踏板時間線繼續處理。

## 2. 建立踏板區間

按 channel 建立 CC64 時間線。基本開關採 MIDI 定義：0–63 關、64–127 開。同一踩下區間內的重複 on 事件不應切成數個區間。

第一版可只對明確的 0／127 全關／全開序列放行；其他值視為可能的半踏板，保留原音尾並計數。閾值只能描述基本開關狀態，不能證明不同半踏板值的音色與衰減完全相同。

缺少明確踩下與鬆開界線、不完整區間或控制事件順序有歧義時，不以「推測踏板還踩著」放行。

## 3. 每次截斷的接受條件

設原始音尾為 `original_end`，目前音尾為 `new_end`，這次候選為 `candidate_end`。

僅當下列條件全部成立，才縮短音尾：

- `start_tick < candidate_end < new_end`，不可產生零長／負長音。
- 候選點與原始音尾均嚴格落在同一次已確認的持續踩踏板區間內：`pedal_down < candidate_end < original_end < pedal_up`。
- 從候選到原始音尾之間，沒有影響上述假設的控制器變化或歧義。
- 該 channel、同音高沒有影響區間的重彈／重疊配對歧義；第一版遇到就不截。
- 候選點沒有與踏板、同音重彈等事件處於同 tick 的未處理邊界。

候選始終和不可變的 `original_end` 比較，避免連續多次縮短累積成未檢查的改變。

沒有踩踏板時，即使截斷看起來符合可彈性規則，也不屬於這版「由踏板維持延音」的可接受情況，應保留。這會減少截斷數量，是本次保守目標的直接結果。

## 4. MIDI 事件如何改

- `note_on`：時間、音高、力度不變，不補發起音。
- `note_off`（含 velocity 0 的 note-on）：通過條件才把絕對 tick 改到候選點；其餘屬性保持原樣。
- CC64：截斷階段不改其時間或值；分手階段只做必要且可明確判定的聲道映射。
- 更新絕對時間後重算 delta tick；不得改變其他事件的絕對時間。
- 保留未改動事件間的原始順序，避免全局把所有原有 note-off 重排到控制器之前。跨軌同 tick 的歧義以跳過處理為優先。

### 具體例子

踏板第 1 秒踩下、第 4 秒鬆開；音符第 1.5 秒起音：

| 原 note-off | 候選 note-off | 決策 | 理由 |
|---|---|---|---|
| 3 秒 | 2 秒 | 符合其餘條件才接受 | 都在同一次踏板內，基本延音終點仍由第 4 秒鬆踏板決定 |
| 5 秒 | 2 秒 | 保留 | 新版第 4 秒可能止音，原版仍持鍵到第 5 秒 |
| 3 秒 | 0.8 秒 | 保留 | 候選早於起音，也早於踩踏板 |
| 3 秒 | 1 秒 | 保留 | 與踩踏板同一時刻，屬第一版跳過的邊界 |
| 4 秒 | 2 秒 | 保留 | 原 note-off 與鬆踏板同 tick，第一版不處理邊界 |

「基本延音終點相同」不代表音源輸出逐樣本相同。釋放聲、共鳴與重彈行為仍需試聽確認。

## 5. 接入既有規則與報告

優先在共用的候選釋放位置加入檢查，避免四種規則各自複製踏板邏輯。`release()` 可以回傳是否實際改動，原有規則計數只統計接受的改動。

所有規則都必須依實際 `new_end` 維護仍持有的音符。拒絕截斷後，不得直接丟掉仍持續的音，也不得讓下一條規則繞過踏板檢查。

報告至少區分實際截斷、因踏板不足／跨界保留、因聲道或事件歧義保留。反覆提議同一顆音時，區分提議次數與唯一音符數，勿讓讀者誤認為刪改了更多顆音。沿用現有報告區塊更新和三語顯示機制；不新增 GUI 控制項。

## 6. 驗收建議

實作 agent 先讀適用的 AGENTS 指示。以下是驗證設計，不表示授權執行耗時的整曲轉譜／批次渲染。

- 以小型 MIDI 事件案例檢查同踏板區間、跨鬆踏板、沒有踏板、半踏板、缺失 pedal-up、重複 on、同 tick 邊界、同音重彈及多軌控制器。
- 檢查單來源分成 2／3／4 手後的踏板映射，以及多來源衝突不被擅自合併。
- 檢查拒絕截斷後，後續規則仍追蹤原長音；未通過的音尾與所有 note-on 不變。
- 檢查事件絕對 tick、有效 delta tick 及未修改事件的相對順序。
- 再以相同音源、相同控制器與固定輸出設定比較少量短片段。音訊差值可輔助定位，不等於可察覺性結論；保留盲聽或人工試聽。
- 不以「最多同時按鍵數下降」單獨證明成功；可能含踏板延音的音長不是實際持鍵真值。

## 7. 預估改動範圍

主要落在 `src/trim_overlaps.py`、`src/hand_split_channels.py`，以及必要的 `src/gui_i18n.py` 報告翻譯。優先沿用現有模組，不引入模型、服務或新的音訊架構。

初步判斷是小到中等改動，實作約一兩百行量級；若處理多來源聲道衝突需要額外資料流，規模會增加，第一版應以保守跳過控制範圍。此數量不含新增驗證案例，也不是完成時間承諾。

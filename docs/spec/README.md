# Piano MIDI Cleanup 設計規格

本規格說明工具的每個處理步驟：目的、輸入假設、規則、門檻與依據、輸出與已知限制。內容描述程式的現狀；研究過程、比較實驗與歷史討論放在 `docs/` 根目錄的專題文件，本規格只引用其結論。

## 目的與範圍

鋼琴 AI 轉譜輸出的 MIDI 能播放，但不能直接當譜看：速度和小節線對不上、混有誤認的音、左右手不分、延音踏板把音符拉得很長而互相重疊。本工具以 MIDI 為輸入，把它整理成能看譜、能編輯的 MIDI。

不在範圍內：

- 轉譜模型本身。工具附有轉譜入口，但各步驟只依賴 MIDI，不綁定模型。
- 樂譜排版。輸出是 MIDI，不是 MusicXML。
- 編曲判斷。刪音只處理「明顯不該在」或「彈不到」的音，不決定哪個聲部重要。

## 設計原則

1. **保守**：每條規則只處理有依據的情況；拿不準時保留原樣。
2. **可重建**：所有後處理都從 `song_bpmfix.mid` 重新產生 `song_bpmfix_cleaned.mid`，改設定重跑不會疊加前次結果。
3. **可追蹤**：每一步把統計寫進同一份 `song_stats.txt`，數字說明它做了什麼。
4. **聽感優先**：只改譜面表現的步驟（截斷）不得改變播放結果超過容差。
5. **門檻要有依據**：每個門檻記錄來源，是實測、文獻還是使用者判斷，見各章參數表。

## 處理流程

```text
音訊 ──轉譜──▶ song.mid
                 │ 1. BPM 修正（第 2 章）
                 ▼
            song_bpmfix.mid ◀── 2. 第一拍對齊（第 2 章）
                 │              3. 調號（第 3 章）
                 │ 每次後處理都從這裡重建
                 ▼
            song_bpmfix_cleaned.mid
                   4. 規則清理（第 4 章）
                   5. 可彈性清理，可選（第 5 章）
                   6. 分手（第 6 章）
                   7. 截斷重疊（第 7 章）
                   8. 捲簾截圖，可選（第 8 章）
```

統一執行器 `src/postprocess.py` 依此順序執行，每一步可開關（第 8 章）。

## 資料約定

| 項目 | 約定 |
|---|---|
| 檔名 | `song.mid`（轉譜原檔）、`song_bpmfix.mid`（速度與小節對齊後）、`song_bpmfix_cleaned.mid`（後處理結果）、`song_stats.txt`（報告） |
| 拍號 | 固定 4/4。第一拍、調號、截斷的節拍線、文字檢查與截圖都以 4 拍一小節計算 |
| 速度 | BPM 修正後全曲單一速度；MIDI 的 `ticks_per_beat` 即一拍 |
| 起音組 | 起音相差 50 ms 內的音視為同時彈奏（`GROUP_START_WINDOW_SECONDS`），分手、可彈性清理、截斷共用 |
| 手與聲道 | 右手 channel 1、第二右手 channel 2、左手 channel 3、第二左手 channel 4（程式內為 0–3） |
| 音名 | 中央 C 為 C4（MIDI 60） |

## 主要已知限制

| 限制 | 影響步驟 | 說明 |
|---|---|---|
| 只支援 4/4、單一速度 | 第 2、3、7 章 | 變速、自由速度、非 4/4 的曲子小節線會錯 |
| 音尾是聲音停止時間 | 第 6、7 章 | 上游把踏板延音寫進音長，真正的放鍵時間不在 MIDI 裡，只能推測（第 1 章） |
| 上游踏板可能放錯 | 第 7 章 | 截斷依賴 MIDI 踏板判斷聽感；踏板模型提早放開時截斷會偏保守 |
| 分離品質 | 第 4、5 章 | 從歌曲分離出來的鋼琴可能混入其他樂器，產生規則無法分辨的多餘音（`docs/open-issues.md`） |
| 聽感未系統驗證 | 第 7 章 | 截斷容差依 MIDI 語義推算，尚未以渲染試聽確認 |

## 維護方式

- 改程式行為時同步更新對應章節；章節描述現狀，不寫修改經過。
- 新門檻或改門檻時，在參數表寫明依據；依據來自實驗時，連結到記錄該實驗的專題文件。
- 研究、比較、計畫等過程性內容寫在 `docs/` 根目錄，結論定案後再摘要進本規格。
